何を表示しているか

小さい箱は実際の宣言です。METHOD / FUNCTION / CALLBACKは1関数1node。CTOR、property / getter、型・schema・table、interfaceのSIGNATUREを区別します。classの囲みは宣言元class、FILEは実在するファイルです。

起点はHTTP entry、event受信、middleware。起点の先は必ず全層を通るわけではありません。configや共有classを起点ごとに複製しません。CLIはこのアプリに登録されていないので表示しません。

選択近傍は使う先・使う元。依存範囲は起点から辿る先（同じclassのconstructorと設定overrideを含む）。薄くなった箱も同じ座標に残ります。「全関係」は密度を確認するための表示です。

緑=直接呼出、青=読み取り、紫=middleware適用、橙=event配送。点線の型参照・登録・継承・実装は直接呼出ではありません。詳細の関係一覧で根拠を確認できます。

eventの受信関数はOrderHandlers.startup内の無名callbackです。startupそのものを受信関数に置き換えていません。Middlewareの適用は登録情報であり、Controllerメソッドからの直接呼出ではありません。

src/domainにはschemaと型があり、DB由来のOrder等はsrc/infra/db/schema.tsです。独自のRepository PortやDomain関数を捏造しません。package serviceの列は所在を示す表示規約で、設計上の責務を推定した分類ではありません。

「内部未展開」は依存なしではありません。ORM・framework内部や内部callbackの完全な再帰展開、実行時トレース、性能・並行更新の検証は対象外です。
